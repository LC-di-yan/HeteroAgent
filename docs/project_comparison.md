---

## 1. 定位差异

| 维度 | 对方（ai-knowledge-base-rag） | 我（HeteroAgent） |
|------|------------------------------|-------------------|
| 定位 | **私有知识库问答平台**（毕业设计） | **金融智能客服多Agent系统** |
| 核心场景 | 简历/文档上传 → 智能问答 | 理财产品咨询、退款/开户/理赔/投诉办理 |
| 创新点 | 三级幻觉检测机制 | Supervisor编排 + 强制合规审查 |
| 文档形式 | 有截图、论文式README | 面试题库对照、测试用例、演示话术 |

## 2. 架构对比

| 维度 | 对方 | 我 | 优劣 |
|------|------|-----|------|
| 后端 | FastAPI | FastAPI | 相同 |
| Agent 框架 | **自研 BaseAgent + SchedulerAgent**（顺序调度） | **LangGraph StateGraph**（Supervisor 条件路由） | ⭐ 我用图编排，支持条件分支/强制边/Checkpoint |
| 前端 | **Next.js + Ant Design**（完整工程） | 原生单页 HTML（明暗主题+SSE） | ⭐ 对方前端工程化强 |
| 向量库 | **PostgreSQL + pgvector**（生产级） | FAISS + Milvus 工厂切换 | ⭐ 对方生产级，我有切换能力 |
| Embedding | **阿里云百炼 text-embedding-v3**（真实语义） | OpenAI API（**当前讯飞端点不支持→hash降级**） | ⚠️ **我的弱点**：检索语义弱 |
| 数据库 | PostgreSQL（关系+向量混合） | Redis（可选）+ 内存 fallback | 对方存储完整 |
| 文档处理 | **PDF/DOCX/TXT 上传解析闭环** | 无上传功能，仅预置知识库 | ⚠️ **我的缺口** |

## 3. Agent 能力对比

| Agent | 对方 | 我 |
|-------|------|-----|
| 文档解析 Agent | ✅ PDF/DOCX/TXT 解析 + 分层切片 | ❌ 无（仅预置文档） |
| 检索 Agent | ✅ 向量检索 + 多路召回 + 重排 | ✅ Hybrid Search（FAISS+BM25+RRF）+ Cross-Encoder 重排 |
| 问答 Agent | ✅ DeepSeek 生成 | ✅ RAG + 置信度阈值 + 自我纠正 |
| **幻觉检测 Agent** | ✅ **三级**：NLI事实一致性 + 知识边界 + 自我验证（514行完整实现） | 🟡 仅单轮 Self-Correction（较弱） |
| **合规审查 Agent** | ❌ 无 | ✅ 两阶段（规则引擎+LLM）+ PII脱敏 + 注入防御 + 否定词感知 |
| **意图路由** | ❌ 固定链路 | ✅ Supervisor LLM 路由 + FAQ早退 + 路由缓存 |
| **工单处理** | ❌ 无 | ✅ 创建/查询/优先级/类型识别 |
| 调度方式 | 自研顺序执行 | LangGraph 图编排 + 超时熔断 + 指数退避重试 |

## 7. 面试怎么讲（借鉴对方补自己）

### 我该补的（优先顺序）
1. **真实 Embedding** — 换支持 embeddings 的端点（如阿里云百炼/OpenAI 官方），检索语义立刻质变
2. **三级幻觉检测** — 把我的 Self-Correction 升级为三级（事实一致性+知识边界+自我验证），对齐面试题库 Q6
3. **文档上传功能** — 加一个上传端点 + 解析（面试演示更完整）

### 面试对比话术
> "对比过类似的 RAG 项目（参考了 ai-knowledge-base-rag 的思路），它的亮点是三级幻觉检测和 pgvector 存储。我的项目定位不同——**金融客服场景更强调合规**，所以核心是 Supervisor 编排 + 强制合规审查 + 注入防御。检索方面我做了 Hybrid Search（向量+BM25+RRF），幻觉控制用了自我纠正 + 置信度阈值转人工。两者可以互补：借鉴它的三级幻觉检测思路，把我的合规体系做得更完善。"

### 被问"和同类项目比优势"时
- 对方：检索+幻觉检测强
- 我：**编排+合规+记忆+可观测+工程化**全链路
- 关键差异：**对方是"问答工具"，我是"带合规约束的业务系统"** — 金融场景落地价值更高
