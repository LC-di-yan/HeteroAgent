# 0008. 跨会话记忆只存确定性事实，不做 LLM 抽取

- 状态：已接受
- 日期：2026-11-06
- 相关：\`memory/context_store.py\`，方案 T-P2-02

## 背景

短期记忆（Redis，TTL 30 分钟）只覆盖一个会话。客服场景里"该用户上周提交过退款工单 TK-..."
这类信息跨会话丢失，导致重复询问、重复建单。

常见做法是引入 LLM 事实抽取流水线（mem0 / 图记忆）：把对话喂给模型，让它提炼实体与关系。
2026 年的对照研究表明，这类流水线在中小规模知识库上收益不稳定，却带来三方面成本：
抽取错误不可审计、每轮多一次模型调用、事实冲突难以消解。

## 决策

- 只存**确定性事实**：工单号（正则从工单创建结果里取）、关注产品（后续由业务显式写入）；
- 不引入 LLM 抽取步骤，不做实体消解，不做图结构；
- 存储用 LangGraph Store，命名空间 \`("org", org_id, "user", user_id, "facts")\`，
  天然按租户隔离；同 kind+value 去重，按时间保留最近 N 条；
- 消费侧只有一处：知识问答生成时把事实拼进提示词（"该用户近期记录"），
  不参与检索排序，避免污染向量分数。

## 后果

- 正面：可审计（每条事实都能追溯到业务流程产生的原文）、零额外模型成本、跨会话可用。
- 负面：覆盖面窄（只覆盖我们主动写入的事实）；不做消解意味着同一用户多条工单会并列展示。
- 重新评估条件：出现"用户主动陈述的偏好"（如"我只看低风险产品"）且证明对转化率有显著影响时，
  再考虑受限的抽取（白名单字段 + 人工复核）。

## 备选方案

- mem0 / 图记忆：引入成本与不确定性，暂不采用（与方案 0.2 的裁决一致）。
- 直接把对话原文塞进提示词：上下文膨胀且含 PII，否决。
